# اشتباهات تکراری و قوانین کار (Lessons & Mistakes)

> این‌ها اشتباهاتی است که در ممیزی ۸ ریپو (آبان ۱۴۰۵ / Nov 2026) پیدا شد. هر بار قبل از کد زدن بخوانید تا تکرار نشود.

## اشتباهات تکراری در کد
1. خواندن رکورد با id بدون محدود کردن به مالک/مستأجر (owner/tenant/mode scope) — باعث دیدن اطلاعات دیگران.
2. برگرداندن فیلدهای داخلی (قیمت تمام‌شده، کارمزد، یادداشت داخلی) به مشتری.
3. دو endpoint قدیمی و جدید موازی با کنترل‌های متفاوت — یکی همیشه سوراخ می‌ماند.
4. کلید idempotency بدون مقایسه با hash درخواست.
5. فراخوانی شبکه (درگاه، پیامک، تأمین‌کننده) داخل قفل دیتابیس.
6. علامت‌زدن پیامک به‌عنوان «ارسال‌شده» قبل از ارسال واقعی.
7. محدودیت نرخ (rate limit) سراسری که همه را قفل می‌کند به جای محدودیت per-user/per-IP.
8. حذف ارقام فارسی با regex `/\D/` — ارقام فارسی/عربی باید اول به لاتین تبدیل شوند.
9. ENVIRONMENT=dev یا secretهای توسعه در production.
10. وابستگی (dependency) که در manifest نیست (requirements/package.json).
11. مستندات وضعیت که با کد تناقض دارد.
12. شاخهٔ main با شاخهٔ دیپلوی‌شده یکی نیست.

## تعریف «تمام شد»
«انجام شد» یعنی ۴ مرحلهٔ جدا، هر کدام با SHA: **کد شد → تست شد → merge شد → دیپلوی شد.** هیچ‌وقت بدون مدرک نگویید «تمام شد».

## قوانین مالی و مالیاتی
- محاسبات مالی/مالیات با عدد صحیح (basis points): `x * rate_bps // 10000` — هرگز float.
- VAT ایران ۱۰٪ (نه ۹٪)، به‌صورت config تاریخ‌دار با سابقه؛ هر نرخ باید legal_basis داشته باشد.
- در گردشگری مالیات روی کارمزد آژانس است (سامانه مودیان).
- Ledger (دفتر کل) تنها منبع حقیقت مالی است؛ AuditLog و LedgerEntry فقط INSERT. Redis هیچ‌وقت منبع حقیقت اعتبار/ledger نیست.
- هرگز قیمت، موجودی یا عدد مالی ساختگی نشان داده نشود؛ mock فقط در dev و با برچسب MOCK.
- به عملیات مالی چک‌لاین (پرداخت، کیف پول، درگاه، تسویه، حسابداری) بدون اجازه دست نزنید.

## قوانین سرور و دیپلوی
- بازرسی/تشخیص/ساخت/دیپلوی فقط روی مسیر پروژه روی سرور اصلی، نه روی clone محلی.
- هرگز مدرک محلی/قدیمی را جای مدرک سرور زنده نگذارید؛ بدون دسترسی واقعی ادعای «بررسی بصری» نکنید.
- سایت‌های زنده (esp-co.ir، checkline.ir، …) را خراب نکنید. checkline.ir: هیچ تغییری روی سایت زنده بدون تیکت سیتی‌نت.
- روی سرور/سایت 8zone قبل از هر تغییر اجازه بگیرید.
- افزونهٔ «سئوی چک‌لاین» نسخهٔ زنده 1.3.2 را هرگز با کپی محلی قدیمی جایگزین نکنید. افزونه‌های جدید اول روی checkline.travel تست شوند.
- نام‌های داخلی karenseir (کد، پکیج، DB، env) را بدون اطمینان تغییر ندهید؛ برند عمومی «کارن تراول» است.

## قوانین طراحی
- هر صفحه/پنل/تصویر جدید اول در Figma طراحی و تأیید شود، بعد پیاده‌سازی.
- در Figma: throw در اسکریپت use_figma همه‌چیز را rollback می‌کند (JSON برگردانید)؛ RTL بومی ندارد.
- محصول واقعی فقط با عکس واقعی برند، نه AI.

## قوانین امنیتی ریپوها
- karentravel.ir و 60-onlone **عمومی** هستند — جزئیات آسیب‌پذیری قابل سوءاستفاده، IP سرور، رمز، اطلاعات کارکنان در آن‌ها نگذارید.
- هر ریپو یک LESSONS.md دارد (شاخهٔ docs/lessons-2026-11-10)؛ قبل از کار بخوانید.

## قوانین ثابت کاربر (برای همهٔ پروژه‌ها)
- بعد از هر کار: commit و push به GitHub.
- برای هر پروژه agent اختصاصی.
- پاسخ به فارسی.
- برای احتیاط قطع دسترسی: راهنما/README، گزارش پیشرفت و مدارک QA همیشه در GitHub + فایل قابل دانلود؛ همیشه گزارش «انجام‌شده / مانده / برنامهٔ بعد».
- گزارش وضعیت فاز: DONE / CHANGED / TESTED / BLOCKED / NEXT. وضعیت ویژگی‌ها با مدرک: DONE/PARTIAL/MOCK/DISCONNECTED/NOT_STARTED/BLOCKED (Spec ≠ Implementation).
