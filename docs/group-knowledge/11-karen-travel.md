# کارن تراول / کارن‌سیر — repo: karentravel.ir

## هویت
- کارن‌سیر «پیشخوان خودمون» برای کارن تراول؛ برند عمومی سایت «کارن تراول» (karentravel.ir). نام‌های داخلی (کد، پکیج، DB، env) هنوز karenseir — بدون اطمینان تغییر ندهید.
- تصمیم ۱۴۰۵/۰۸/۱۲: دیگر منتظر همکار نمانیم؛ Claude همهٔ کار کارن‌سیر را خودش انجام می‌دهد، تیم بعداً تحویل می‌گیرد.
- هر تحلیل/طراحی کارن‌سیر هر بار در GitHub push شود.
- کارن تراول با مجوزهای تاژبان (بند الف، بند ب، فروش آنلاین، میراث فرهنگی)؛ سایت مال تاژبان، تاژبان قرارداد امضا می‌کند؛ آژانس‌های شریک وایت‌لیبل می‌گیرند.
- معماری: کارن تراول پلتفرم مستقل (کد/دامنه/DB خودش)؛ تاژبان والد مجوزدار؛ چک‌لاین کانال فروش مجاز (وایت‌لیبل بودن باز)؛ سیتی‌نت تأمین‌کنندهٔ فناوری/API؛ داده مال هلدینگ.

## سرور
- جزئیات سرور عمداً در این ریپوی عمومی نیامده؛ نسخهٔ کامل در ریپوهای خصوصی گروه (docs/group-knowledge/11-karen-travel.md).

## محصول
- ظاهر مثل سایت سفر معمولی (علی‌بابا/لست‌سکند)؛ قطار مثل علی‌بابا و مستر بلیت. تأمین‌کنندهٔ قطار: روحان (شاید پنل بدون وب‌سرویس).
- مشتری به سایت دیگر (حتی خواهر) فرستاده نشود. آژانس‌های طرف قرارداد تور خودشان را ثبت می‌کنند؛ نام/آدرس آژانس دیگر در صفحهٔ تور نیاید.
- B2B/بین‌آژانسی اولویت جدی: آژانس‌ها پرواز خودشان (مثل صندلی چارتر) را دستی یا با وب‌سرویس ثبت کنند؛ روابط سازمان به سازمان.
- سقف قیمت پرواز = سقف سازمان هواپیمایی کشوری؛ مارک‌آپ آژانس شریک طبق قرارداد خودش.
- چارتر از سیستم‌های اشتراکی بیرونی (مثل پرتو) به‌عنوان provider.
- VAT روی کارمزد آژانس (سامانه مودیان)؛ کاربر اسناد را می‌دهد.
- طراحی هر صفحه/پنل جدید اول در Figma.
- تأیید ۱۴۰۵/۰۸/۱۸: تلفن پشتیبانی بالای صفحهٔ اصلی؛ انتخاب یک‌طرفه/رفت‌وبرگشت بیرون از تقویم.
- تأیید ۱۴۰۵/۰۸/۱۹: آژانس‌ها رزرو را فقط از طریق اتصال آژانس↔تأمین‌کنندهٔ خودشان انجام دهند؛ مالی تفکیک قیمت داخلی را می‌بیند؛ بسته‌های چندتأمین‌کننده فعلاً توسط ادمین پلتفرم.

## ماهان (W5) MRS
- اول ۸ سناریوی تست ماهان روی QAA و پر کردن شیت ماهان، بعد اتصال به جستجو و خرید.
- وضعیت 2026-11-08: QAA فقط روی IKA-BKK قیمت می‌دهد؛ سناریو ۵ رزرو (PNR TL27U)؛ ۶–۸ در اجرای ۴ رزرو (TL2C2, TL2C3, TL2C4، بدون بلیت)؛ مسیر داخلی از پشتیبانی ماهان پرسیده شود.

## معماری
- دامنه‌ها: پرواز، هتل، تور، قطار، ویلا، خودرو، کروز، ویزا، رستوران، رویداد، استخر/ورزش، راهنما، صنایع‌دستی، حمل گردشگر، سازمان‌ها، تأمین‌کننده/آژانس/بک‌آفیس، کیف پول/اعتبار/اقساط، پرداخت/تسویه، عملیات سفر، اعلان، دستیار AI، موتور جستجو.
- استک: Next.js 14، FastAPI، SQLAlchemy، PostgreSQL (RLS/FORCE RLS)، Redis، Docker، Tailwind، Vazirmatn RTL؛ JWT + RBAC، multi-tenant، provider adapter، Outbox، Search v2.
- تصمیم مرداد ۱۴۰۵: modular monolith + scaling (Choice B) قبل از میکروسرویس؛ مسیر: ۳–۵ instance، cache Redis، read replica، PgBouncer، worker. تیم ~۱–۲ نفر.
- تأمین‌کنندگان اقامت: اقامت۲۴ و GRS v1.18.4 (search → revalidate → hold → payment یا تأیید اعتبار سازمانی → book → modify/cancel → webhook)؛ GRS فقط برای کارن‌سیر؛ یک adapter مستقل برای هر provider.
- وضعیت تأمین‌کننده: UNSELECTED → UNDER_EVALUATION → CONTRACTED → SANDBOX → PRODUCTION → DEPRECATED؛ تا CONTRACTED کد adapter نه.
- ممیزی PHASE 0–10: git/docker/nginx → سایت عمومی → UX/RTL → مهاجرت برند → QA عملکردی → API → یکپارچگی داده → SEO/دامنه → عملکرد → دسترس‌پذیری → امنیت؛ وضعیت tunnel هم جزو چک دیپلوی.
