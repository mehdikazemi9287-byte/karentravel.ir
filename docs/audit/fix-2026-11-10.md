### Scope rule — decided by the owner (CEO), 2026-11-10, approved as implemented
- `supplier`: every booking item of the reservation must belong to a supplier the user has a `SupplierMembership` for.
- `agency_partner` (decision a): same check, where the supplier set is the user's own `SupplierMembership` rows plus `Agency.supplier_id` of each agency the user is an `AgencyMembership` member of (the Safarsaz partner relation). An agency with no linked supplier is denied. Selling on an agency's sales channel does not grant fulfilment.
- Finance (decision b): roles with `ledger:read` see the internal price breakdown of any reservation in their own tenant.
- Multi-supplier packages (decision c): fulfilled by platform admin for now. The supplier queue no longer lists them to partners (N2).
- `platform_admin` (`platform:manage`): tenant-wide override; every attempt is audited in its own committed transaction before the action, and the override is refused if the audit row cannot be written (N1).
- Any other role holding `reservation:fulfill` is denied (fail closed). `tenant_admin` and back-office roles never had this permission.
- Admission tickets (`/admission-tickets/validate|redeem`) use the same rule (N3).
- Out-of-scope issue/reissue answers 404 exactly like a missing reservation (N6).

### Customer price-breakdown fields
`view, currency, id, booking_id, total_selling_price, service_fee, discount_amount, discount_source, promo_code, vat, airport_tax, i6_tax, red_crescent, other_taxes, calculated_at`.
`currency` comes from the reservation's price snapshot. No frontend code calls this endpoint (checked with `git grep`), so no UI change was needed.

The internal settlement path (`reservation_funding` capture/release) relied on replay returning an entry of a different type. It now catches `LedgerCommandConflict`, logs `reservation_funding_settlement_conflict` (N5) and skips, which keeps the previous outcome.
