## علت‌های مشترک

1. **سرویس جست‌وجو در پشتهٔ e2e نبود.** فرانت از `/search/v3` می‌خواند و API آن را به `karenseir-search` می‌فرستد؛
   config فقط API و Next را بالا می‌آورد، پس هر جست‌وجو `503 SEARCH_SERVICE_UNAVAILABLE` می‌گرفت.
   `playwright.config.ts` حالا `search-service` را هم با توکن داخلی تصادفیِ هر اجرا بالا می‌آورد (`SEARCH_SERVICE_URL`،
   `SEARCH_INTERNAL_TOKEN`، `MONOLITH_BASE_URL`). نتیجهٔ جعلی اضافه نشد؛ همان سرویس واقعی است.
2. **fixture هتل قدیمی بود.** از `fix(hotel)` به بعد، عرضهٔ هتل باید `hotel_rate` تاریخ‌دار داشته باشد و price-check باید
   `hotel_stay` همان نرخ را بفرستد؛ fixture این‌ها را نداشت، price-check با 409 رد می‌شد و رزرو با 422.
3. **UI عوض شده بود:** صفحهٔ اصلی مرجع Figma (PR #7، #58)، پنل‌ها در PanelShell با منوی نقش‌محور (#50 و پنل‌های بعدی)،
   متن‌های جدید checkout و هویت مسافر (#55)، حذف صفحهٔ دمو `/manage-booking/book1`.
4. پورت‌ها و timeout: پورت‌ها با `E2E_API_PORT` / `E2E_WEB_PORT` / `E2E_SEARCH_PORT` قابل تغییرند (پیش‌فرض CI همان 8100/3101،
   سرویس جست‌وجو 8102). `expect.timeout` به ۱۰ ثانیه رسید چون `next dev` هر route را در اولین بازدید compile می‌کند.

- e2e: اجرای کامل ۳: `37 passed / 1 failed` — تنها شکست `public-auth` بود که در اجرای ۴ علتش ثابت شد: کانتینر محلی
  (محدودیت حافظهٔ cgroup) فرایند `next-server` را پس از compile حدود ۶۰ route در ~3GB RSS با OOM-kill بست
  (`dmesg: Memory cgroup out of memory: Killed process … next-server`) و آزمون‌های بعدی `ERR_CONNECTION_REFUSED` گرفتند.
  همان آزمون‌های انتهای فهرست (public-auth، search-ordering، payment-handoff، panels/refund-loop) روی پشتهٔ تازه: `9 passed`.
  هیچ آزمونی skip نشد. runner گیت‌هاب ۱۶GB حافظه دارد؛ اگر در CI هم دیده شد، پیشنهاد: اجرای e2e روی `next build && next start` به‌جای `next dev`.
- backend: `pytest tests` — 770 passed, 7 skipped (Postgres-only، محلی SQLite)، 0 failed.
- lint: 0 error (40 warning). `tsc --noEmit`: پاس. `npm run build`: پاس (route جدید `/visa/products/[id]`).
- این بررسی‌ها پشت سر هم اجرا شدند؛ اجرای هم‌زمان lint/tsc/pytest با e2e سرور dev را می‌کشد.
