# ممیزی پنل‌های کارن‌سیر / Karen Travel: Panel Audit

- Source: worktree `/home/claude/panelaudit` at `origin/production` `3c7f504` (2026-11-08). Read-only, nothing pushed.
- Method: static reading of the code (`app/**/page.tsx`, `components/panel/*`, `components/operational/*`, `lib/api/*`), plus a static list of backend routes taken from the `@app/@api/@router` decorators in `backend/app/*.py` (563 routes). The frontend `api.get/post/put/...` and `useLoad(...)` paths were matched against that list, method by method. Nothing was checked at runtime. The live host could not be reached from this sandbox.
- Legend: **REAL** = calls existing backend endpoints with the logged-in user's scope. **PARTIAL** = real data, but key actions are missing. **STATIC** = text or links only. **DEAD** = dead route or link.

## 0. خلاصهٔ اجرایی (Headline findings)

1. **No mock data in the panels.** Every panel page I found calls a backend route that exists. The matcher's only two "misses" were string-concatenation artifacts. When a value is missing, the code shows `Unavailable` or `Empty` (`components/panel/PanelKit.tsx`) and does not invent a figure. Grepping for MockNotice, "نسخه نمایشی" and "به‌زودی" finds nothing rendered in any panel.
2. **The after-sales loop is not closed (P0).** A customer can send a cancel, change or refund request (`POST /reservations/{id}/service-requests`, `backend/app/main.py:1396-1432`). The back office can only move it to `under_review` (`POST /backoffice/booking-requests/{id}/review`, `main.py:3746`). **No endpoint and no UI approve, reject, resolve or close a `BookingServiceRequest`.** Refunds create a `RefundRecord(status=requested)` that only a payment-gateway callback can complete (`main.py:1737-1745`). There is no finance refund queue. `refund:manage` appears in `security.py` but nothing in the code ever checks it.
3. **Gating happens only in the browser, plus API 403s.** There is no `middleware.ts`. `PanelShell` only checks "is there a session". It does not check the role. Every role sees the full nav for an area: the admin area has **31 links**, and `backoffice_expert` and `finance_operator` get 403 on many of them. The server side is sound: `require_permission`, `require_role`, supplier and agency membership scope, and tenant scoping (`backend/app/security.py`, `main.py:417-432`).
4. **The agency (contracted travel agency) role is split and partly broken.** The `agency_partner` permissions are `inventory:read, reservation:fulfill, agency:manage, credit:read`. Tour CRUD for agencies lives under `/supplier/tours` (Safarsaz in `partner` mode), and it requires a **SupplierMembership**. The agency nav has **no** "my tours" link, and `/supplier/*` pages show the full supplier nav. Most of those pages need `inventory:manage`, which agency users lack, so they return 403.
5. **Three shells and three palettes.** The panels use `PanelShell` (plum and coral, `components/panel/panel.css`). Several ops, finance and supplier pages instead use `JourneyShell`, the public site header and footer. Older components such as `ConnectedViews`, `PanelViews`, `TripOperations` and `OperationsRecords` use Tailwind plus the navy `.dashboard`, `.panel` and `.button` classes from `globals.css`. They render inside the plum shell and look inconsistent.
6. **Many backend features have no UI.** Examples: reconciliation match and resolve, voucher reissue, visa product and document review, supplier lifecycle, notification templates, review moderation and supplier response, enterprise RFQ quotes, invitations, selection and withdraw, approval templates, org credit commands, `/approvals/{id}/decision`, and traveller edit (`PUT /me/travellers/{id}`). The list is in §9.

## 10. Shared shell / design system issues

**What exists:**
- `components/panel/PanelKit.tsx` + `panel.css` is the de-facto panel design system. It provides `PanelShell` (sticky plum sidebar and coral active state; below 900px the nav becomes horizontal scrolling chips; the admin area gets a 5-tab bottom nav below 700px), `Card`, `Stats`, `Table` (with `data-label` for stacked mobile rows), `Badge` (status dictionary in Persian), `Empty`, `Unavailable`, `Loading`, `Failed` (401/403 copy), `Async`, `useLoad`, and the `fa`, `money` and `dateFa` formatters. Tokens are scoped under `.pn`: `--pn-ink #2a1530`, `--pn-plum #3a1b3d`, `--pn-coral #ef5b3d`, `--pn-cream #fdf5ea`, and so on. These match the approved Homepage plum and coral identity (`DESIGN_SYSTEM.md` "فاز Plum / Coral").
- `app/layout.tsx` sets `lang="fa" dir="rtl"` for the whole document, and the font is Vazirmatn with a Tahoma fallback.

**Problems:**
1. **Token conflict.** `DESIGN_SYSTEM.md` lists navy and teal tokens (`ink #08253D`, `ocean #0E7490`). `app/globals.css:2` defines `:root` once with `--ocean:#ef5b3d` (coral), and then `globals.css:6` **redefines** `:root` with navy and teal (`--ink:#071f35`, `--ocean:#0b8f8b`). `panel.css` uses its own `--pn-*` set. There is no single semantic token layer, and white-label can't theme panels through tokens, which `DESIGN_SYSTEM.md` §Themeability requires.
2. **Three page shells.** `PanelShell` (most panel pages), `JourneyShell` (public header and footer: `/backoffice/{trips,trip-events,support,notifications,records,booking-requests}`, `/finance/{records,accounting}`, all `/supplier/*/new` editors, `/manage-booking`, `/trips`), and the public `Shell` (`/white-label`, `/integrations`). Moving between these pages swaps the header and loses the sidebar.
3. **Parallel component kits.** `components/operational/PanelViews.tsx` defines its own `useLoad`, `Table`, `Shell`, `Gate` and `Tabs`. `CommercePanel.tsx` has another `Tabs`. `ConnectedViews.tsx` has `LoadingState`, `ErrorState`, `EmptyState` and its own `MockNotice`. `JourneyShell.tsx` has another `MockNotice`. About 40 operational components use Tailwind utilities plus the navy `.dashboard`, `.panel`, `.button.primary` classes from `globals.css`. Some use inline `style={{…}}`, for example `SupplierOfferEditor` and `SupplierStayContent`.
4. **Nav is not role-aware.** `PanelShell` NAV is fixed per area: admin 31 links, customer 16, supplier 12, org 12, agency 10. Three nav sources disagree: the PanelShell NAV, `roleLinks()` and the `/backoffice` buttons. The back office and finance have no area of their own; they borrow the `admin` nav. On mobile, 31 chips in a horizontal scroller is not usable.
5. **Coupling to the protected homepage.** `PanelShell` imports `AccountMenu` from `components/marketplace/ApprovedFigmaHome.tsx`. `JourneyShell` imports `ApprovedHeader` and `ApprovedFooter` from the same file. Panel work must not edit that file. Wrap or copy these instead.
6. **UX states.** PanelKit pages handle loading, error and empty states well. Legacy components (TripOperations, OperationsRecords, BookingRequestQueue, EnterpriseWorkspace, CustomerAccount) handle errors only partly, and some show raw API detail strings. There are no skeletons; `DESIGN_SYSTEM.md` lists Skeleton and Drawer, but neither exists. There is no `loading.tsx` per route (only `app/error.tsx`). There is no pagination in PanelKit `Table`; only OperationsRecords and BookingRequestQueue page with offset.
7. **Dates.** `dateFa` uses `toLocaleDateString('fa-IR')`, which gives Jalali dates in the browser. But inputs are native `type=date` (Gregorian) or raw ISO strings. A `components/search/JalaliCalendar.tsx` exists but no panel uses it.
8. **Static boilerplate.** Every `PanelShell` page ends with the same "وضعیت و دسترسی" card and the footer line "اطلاعات واقعی از حساب و سازمان شما دریافت می‌شود". That is noise.

**Protected (do not change without explicit approval; `AGENTS.md:168`):** the approved KarenSeir visual identity, the **Homepage** (`app/page.tsx` → `Home`, `components/marketplace/ApprovedFigmaHome.tsx`, `ApprovedHomeLower.tsx`, `MarketplaceHome.tsx`, `approved-figma.css`) and the **Search visual experience** (`components/search/HomeSearchExperience.tsx`, `JalaliCalendar.tsx`, `/search/results` + `components/operational/UnifiedSearchView.tsx`). Panel restyling should stay inside `components/panel/*` and the panel CSS.
