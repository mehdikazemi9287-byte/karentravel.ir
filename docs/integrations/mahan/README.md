## آداپتور پرواز سایت (کد: `backend/app/mahan_flight.py`) — وضعیت: فقط Source، خاموش
اتصال کلاینت MRS به جریان «جست‌وجو ← استعلام نهایی ← نگه‌داشتن صندلی (PNR)» پشت `flight_port`، با کلید `MAHAN_MODE`:

| مقدار | رفتار |
|---|---|
| `disabled` (پیش‌فرض) یا مقدار نامعتبر | هیچ پرواز ماهانی نشان داده نمی‌شود؛ پاسخ دلیل دارد (`disabled` / `invalid_mode`). هیچ تماسی با ماهان گرفته نمی‌شود. |
| `qaa` | محیط آزمایشی ماهان. **فقط کارشناس** (`backoffice:read`)؛ مشتری `qaa_test_only` می‌گیرد. رزروها آزمایشی‌اند. فقط IKA-BKK قیمت دارد. |
| `live` | Production ماهان. **دسترسی هنوز داده نشده**؛ بدون کلید، بسته می‌ماند (`missing_credentials`). |

API (همه با ورود):
- `POST /flights/suppliers/mahan/search` — قیمت «تقریبی هر بزرگسال» از Availability (فقط کلاس باز، قیمت‌دار، با ساعت رسیدن)؛ `offer_ref` امضاشده (HMAC) بدون قیمت.
- `POST /flights/suppliers/mahan/revalidate` — FareQuote (قیمت مرجع) + قاعدهٔ markup ماژول commerce + سقف نرخ سازمان هواپیمایی (`charter_price_caps`، بزرگسال) → `ok` یا `price_changed`.
- `POST /flights/suppliers/mahan/hold` با هدر `Idempotency-Key` — دوباره FareQuote؛ اگر مبلغ با `expected_total` یکی نبود `PRICE_CHANGED` و Book انجام نمی‌شود؛ وگرنه یک بار Book. پاسخ گم‌شده (timeout) هرگز تکرار نمی‌شود: وضعیت `unknown` و بررسی دستی با NRSRT.
- `POST /flights/suppliers/mahan/holds/{id}/issue` — **همیشه 423**: صدور بلیت تا تأیید کتبی مالک و اتصال پرداخت خاموش است (TODO در کد).
- `GET /flights/suppliers/mahan/status` — فقط کارشناس؛ حالت و نام تنظیمات جاافتاده (نه مقدارشان).

قواعد: هزینهٔ تأمین‌کننده، سود و جزئیات PNR به مشتری برنمی‌گردد (فقط در `audit_events`، بدون اطلاعات شخصی مسافر). مالیات ارزش افزوده فقط روی کمیسیون (سود) با نرخ تاریخ‌دار `vat_rate_on` حساب و داخلی ثبت می‌شود؛ روی کرایهٔ ایرلاین چیزی اضافه نمی‌شود. هیچ تماس شبکه داخل تراکنش دیتابیس نیست. تکرار فقط برای Availability/FareQuote روی خطای شبکه/503/timeout. Migration ندارد (از جدول موجود `idempotency_keys` استفاده می‌شود).

### روشن‌کردن (فقط با تأیید مالک، روی سرور، نه در مخزن)
1. QAA برای آزمون کارشناس: در env سرور `MAHAN_MODE=qaa` و `MAHAN_QAA_API_KEY` (یا `_B64`)، `MAHAN_QAA_OFFICE_USER`، `MAHAN_QAA_OFFICE_PASS`؛ سپس restart سرویس api. جست‌وجو IKA→BKK با کاربر کارشناس.
2. Live فقط بعد از دسترسی Production ماهان و تأیید مالک: `MAHAN_MODE=live` و `MAHAN_API_KEY`، `MAHAN_OFFICE_USER`، `MAHAN_OFFICE_PASS`.
3. برگشت: `MAHAN_MODE=disabled` و restart.

### هنوز انجام نشده
- اتصال صفحهٔ نتایج/پرداخت فرانت به این API (صفحهٔ جست‌وجوی محافظت‌شده بدون تأیید مالک تغییر نمی‌کند).
- ساختن رزرو (reservation) و اتصال به پرداخت؛ صدور بلیت؛ لغو/استرداد؛ قوانین نرخ (fare rules) — MRS در کلاینت فعلی فراخوان قوانین ندارد.
- مهلت صدور (ticket time limit) از پاسخ Book خوانده نمی‌شود (قالبش در دست نیست)؛ کارشناس باید با NRSRT ببیند.
- قالب دقیق `PassengerBreakdown` تأیید نشده: برای گروه مختلط (کودک/نوزاد) فقط وقتی قیمت هر مسافر با جمع کل جور باشد پذیرفته می‌شود، وگرنه بسته.

## گام‌های بعد
