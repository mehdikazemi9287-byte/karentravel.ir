**محیط:** فقط Source (شاخهٔ `feat/stitch-account-pages`). روی سرور هیچ تغییری داده نشده و چیزی دیپلوی نشده است. طبق AGENTS.md، تا وقتی صفحهٔ زنده کنار PNG طرح دیده نشود، این کار «انجام‌شده» حساب نمی‌شود.

## روش آزمون
- `npx tsc --noEmit`: بدون خطا.
- eslint روی فایل‌های تغییرکرده: ۰ خطا. یک هشدار `no-img-element` در `ConnectedViews.tsx` (خط ۲۳۲) از قبل وجود داشت و به این تغییر مربوط نیست.
- `npm run build`: موفق.
- اجرا: `next start` روی پورت 3130، همراه backend محلی (FastAPI و SQLite، `ENVIRONMENT=development`) روی پورت 8130 و ورود با `dev-login` (کاربر seed: `employee@aftab.test`).
- **دادهٔ آزمون:** دادهٔ آزمون با همان APIهایی که `e2e/critical-flows.spec.ts` استفاده می‌کند ساخته شد. شامل دو پیشنهاد آزمایشی (هتل و پرواز)، دو رزرو، یک کیف پول ریالی خالی و یک پرداخت در حالت **sandbox** (آزمایشی) است. اسکریپت‌ها در `harness/` قرار دارند. همهٔ عددهای داخل تصویرها پاسخ واقعی همین backend محلی‌اند و هیچ‌کدام در UI ساخته نشده‌اند. مثلاً `SANDBOX-TEST-…` شمارهٔ رسید آزمایشی است.
- تصویرها با Playwright و Chrome در عرض ۱۴۴۰ و ۳۹۰ پیکسل به‌صورت full-page گرفته شدند. در هیچ صفحه‌ای pageerror یا console error ثبت نشد.
- نکتهٔ تصویرهای موبایل پنل: نوار پایین پنل (`pn-bottom`) ثابت (fixed) است. در عکس full-page وسط صفحه افتاده و روی محتوا آمده است. این خطای نمایش در عکس است و در مرورگر واقعی نوار پایین صفحه می‌ماند.

## محافظت‌ها
- صفحهٔ اصلی، جست‌وجو و `app/globals.css` تغییر نکرده‌اند. همهٔ استایل‌ها در `components/operational/stitch-account-2026-11.css` هستند، فقط از همین شش صفحه import می‌شوند و انتخاب‌گرهایشان به کلاس‌های `.sa-*` یا `.journey-page .checkout-page` محدود است. در نتیجه حتی اگر Next.js بعد از ناوبری stylesheet را نگه دارد، روی صفحهٔ اصلی اثری ندارند.
- هیچ فراخوانی API، guard یا منطق مالی اضافه یا حذف نشده است. زبانه‌های «سفرهای من» فقط داده‌ای را که قبلاً دریافت شده بود دسته‌بندی می‌کنند.
- e2e: متن کلید اعلان از `sms` به «پیامک» تغییر کرد و آزمون `critical-flows` هم به‌روز شد. عنوان «پروفایل، مسافران و امور مالی» حفظ شد. **آزمون‌های e2e اجرا نشدند.**
